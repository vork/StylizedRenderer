# Inkforge

A native Slang comic PBR renderer with a Python/SlangPy host. Rendered previews are in `output/`; they are GPU captures, not generated concept art.

## Run

Python 3.12 is recommended. Install dependencies with `uv sync --extra test` or `python -m pip install -e '.[test]'` in a virtual environment.

```sh
python -m tools.fetch_scenes
python -m inkforge.app ~/Downloads/Bistro_Godot.glb --viewer \
  --eye -5 2.2 6 --target 2 4 0 --width 1280 --height 800
python -m tools.gallery --scene bistro --ssaa 2
python -m tools.gallery --scene sponza --ssaa 2
python -m tools.gallery --scene materials --ssaa 2
python -m tools.pan --scene bistro
python -m tools.benchmark --scene bistro
python -m pytest -q
```

On Windows, use a normal Windows scene path. Automatic backend selection is Metal on macOS, D3D12 on Windows, and Vulkan on Linux; override with `--backend`. Only Metal on an Apple M5 Pro has been executed and validated here. Other backends require compatible drivers and still need hardware validation.

Viewer: hold RMB for captured first-person look, WASD to fly, Q/E down/up, Shift for a speed boost, wheel to change movement speed, F1 to hide settings, P to save PNG + camera/settings JSON in `~/Pictures/Inkforge`. The native window is resizable and settings use a wider panel with labels above sliders. `--session capture.json --viewer` restores a saved view. `--style pbr` disables comic effects for comparison; `rush`, `soft`, and `graphic` provide artistic starting points. Debug views include AO, normals, albedo, patterns and individual shadow stages.

**F2** toggles the independent performance overlay; a checkbox also lives under Camera and diagnostics. It reports FPS, average/p95 frame time, CPU encode/submit time, acquire/present waits, render resolution and AA mode. Statistics use uncapped wall-clock durations over a rolling two-second window, refreshed four times per second; they include presentation pacing and do not force a GPU synchronization. CPU and presentation measurements are not GPU timestamps. Clean PNG captures exclude both UI panels.

Run `python -m inkforge.app` without a filename to open a showroom, then drag a **GLB, glTF, USD, USDA, USDC or USDZ** onto the native window. The first supported file in a drop replaces the scene and frames its bounds. Import/upload failures keep the current scene and display an error. Loading is synchronous and can pause the window for large scenes. Drop handling shares the existing GPU device with the window.

Time progresses smoothly through a twenty-minute day by default. **U** pauses the day cycle; **T / Shift+T** ease time forward/back two hours; **L** cycles lighting modes; **G** cycles ground Auto/On/Off; **C** pauses cloud motion. Time, lighting and ground also have UI controls. `--time-of-day 17.6 --lighting add --ground auto` sets them from the CLI.

| Lighting mode | Behavior |
|---|---|
| `auto` (default) | With no lights, use procedural sky plus sun/moon. With only local lights, retain them and add the sky plus sun/moon. With an authored directional light, retain it as the shadowed key and add sky fill. An authored USD dome retains its constant color/intensity fallback. |
| `replace` | Disable imported lights and use procedural sky plus sun/moon. |
| `add` | Add procedural sky plus sun/moon while preserving authored directional, point and spot lights. |
| `sky_only` | Replace ambient sky illumination and background; retain authored lights and add no celestial key. A scene without lights receives only sky illumination. |

The illustrated sky has a time-dependent palette, sun disk, crescent moon, fixed stars and continuously advected clouds. Cloud silhouettes use a procedural height field with curved normals, thickness shading, short light-direction occlusion probes and sunlit rims. This gives a fuller, layered appearance while retaining broad cel tones; it is not a ray-marched 3D cloud volume. The same moving cloud field projects shadows onto geometry along the primary directional light, including authored directional lights. Cloud shadows attenuate direct light, leaving local lights and ambient fill intact. Sky illumination is an analytic ambient approximation, not convolution of the cloud image.

Ground Auto uses a conservative small-object heuristic (bounds up to 12 metres and at most 32 material batches), skips broad existing floors, and places a matte plane just below the object. It can misclassify unusual assets; use G or `--ground on/off` to override it. Camera framing uses the original object bounds, excluding the generated plane.

## Pipeline and style

1. Static geometry into five G-buffers, with linear-light sRGB texture filtering and mipmaps.
2. Four texel-snapped directional shadow cascades, practical splits and overlap blending. Large scenes concentrate the near cascades together for close fly-through views. The hard boundary thresholds continuous four-texel PCF coverage, avoiding the staircases amplified by thresholding a two-by-two comparison. Raw cast coverage is evaluated once in a separate pass; the next cascade is sampled only inside the overlap. A depth-aware two-pixel receiver filter provides a minimum display footprint for the tiny stippled penumbra, while the hard core retains its original coverage. Receiver-plane correction uses actual triangle normals. RG32 shadow maps also store packed caster triangle normals: their slope difference bounds local filter-footprint error, reducing false self-shadow flecks on bent fabric. This is a local depth-comparison tolerance, not a surface normal displacement; very close curved layers remain a limitation. Shadow color retains 60% ambient fill. Surface-anchored stippling peaks at 55% strength near the boundary, fades quickly and is absent outside 18–82% filtered coverage. Area-normalized disk filtering preserves tiny marks instead of suppressing their area twice. Tiny antialiased marks use fixed surface grids at 128 sites per chart unit, with denser octave grids blended in during magnification so dots do not grow into blobs. Darkness changes occupied sites and dot radius; unresolved marks converge to average coverage. A smooth geometric-normal terminator prevents lit PCF fingers on spheres, deliberately moving the comic terminator slightly toward the lit side. This is an artistic penumbra, not contact-hardening PCSS. `--debug cast-shadows`, `terminator`, and `printed-shadows` isolate its stages.
3. Half-resolution GTAO horizon search with analytic integration (4 slices, 7 steps on each side), radius falloff, a bilateral spatial filter, and depth/normal-aware upsampling to full resolution. Fixed angular quadrature avoids screen-pixel random rotation crawling during motion. Screen-space occlusion still depends on visible geometry; there is no off-screen AO or separate AO history.
4. Metallic/roughness Cook–Torrance GGX, artistic GGX lobe expansion, diffuse bands, cool shadow fill, rim lighting, palette simplification, and depth/normal outlines.
5. Surface-mapped pencil hatching: four seamless RGBA textures contain horizontal, vertical and diagonal strokes at nested densities of 2, 4, 8 and 16 strokes per tile. AO darkness selects density and introduces a crossing direction. A faint contact tone (at most 8% ambient attenuation in full comic hatch mode) remains underneath; cast-shadow cores remain solid. Stroke width is 64% heavier than the earlier fine-pencil maps, retaining the same centers and nested spacing. Hatches use neutral near-black pigment with opacity `1-(1-strength)^2`, and crossing strokes enter gradually as occlusion increases. UV charts wrap the strokes around curved forms, with approximate world texel density normalized per primitive. Optional shadow dots remain available with `--dots`, but default to zero.
6. HDR bloom: quarter-resolution highlight extraction and separable filtering produce a halo intensity field. A threshold of 3 admits more highlights while a smooth cap bounds extreme emissive energy. Toward the halo edge, luminous halftone dots shrink and fewer sites remain occupied, increasing their effective spacing. A fixed ordered rank pattern distributes the sites; newly appearing dots grow from zero radius to avoid abrupt popping. Dot brightness has a separate finite display-linear contrast budget (20% of remaining highlight headroom at default strength before dot coverage), reduced saturation and smaller maximum radius. HDR extraction still determines the halo and density; the dots screen-blend into the GT7-mapped scene using remaining highlight headroom, so tone-map compression does not erase them on bright receivers. A GPU regression checks visibility and bounded contrast at the production 3-pixel spacing and .04 strength. No continuous bloom layer is added. The background sky does not emit bloom, but receives halos spilling from scene highlights.
7. Polyphony's actual GT7 HDR-to-SDR mapping. A GPU regression checks the port against the official C++ implementation.
8. Temporal anti-aliasing in display-linear SDR: eight-phase Halton projection jitter, static-world reprojection onto the unjittered history lattice, world-position rejection, neighborhood clipping and linear-light blending. Outlines retain more history, with a running-average startup after reset. Current ink samples are reconstructed at the display pixel center; a restrained spatial edge filter uses the temporally resolved ink mask after TAA. Filtering stays near ink so textures and pen stipples retain their detail. Camera cuts and style changes reset history; smooth time progression does not. Bloom dots are composited after TAA, so their screen-space lattice no longer lowers outline history retention. The final pass encodes sRGB. Debug views disable TAA; stills accumulate eight frames before readback.

Distant ink retains partial temporal coverage across jitter phases that miss a subpixel rail or wire. Background-layer validation and ink-weighted clipping relaxation fade in from 12 to 24 metres and fade out between 0.5 and 2 pixels of motion per frame. Both history and current depth must be distant. Bounded cubic history reconstruction avoids repeated bilinear blur during slow pans. Sky samples retain the last contributing surface position so missed wires use finite-depth camera motion rather than sticking to the infinite-depth sky. Camera-cut resets remain active. These thresholds assume scene units are metres.

When the camera remains exactly still for eight frames, the resolve switches to an exact sliding average of the eight raw jitter phases in display-linear SDR. This removes the periodic history rejection/clipping variation on stationary outlines, hatches and shadows. Every new frame replaces one phase, so clouds and lighting remain live with a seven-frame maximum sample age. Any camera movement immediately restores motion-aware TAA with quarter-amplitude jitter; the stationary cache waits for eight full-amplitude samples after stopping; cuts, style changes and resizes invalidate the stationary samples. The eight-layer RGBA16F cache adds 64 bytes per render pixel (about 134 MiB at 1974×1113), allocated on first TAA use and replaced on resize. This is temporal supersampling for static geometry, not support for animated meshes.

Defaults are `--hatching .75 --dot-frequency 32 --hatch-density 2 --bloom .04 --bloom-threshold 3 --bloom-dot-size 3`. Surface frequency controls hatches and optional shadow halftones; penumbra stipples have their own finer grid. Hatch spacing is fixed in the surface chart: camera motion changes mip filtering, never the stroke frequency. Density still follows occlusion through the nested tonal maps. `--outline-wobble .3` modulates pressure using fixed surface-space waves, with attenuation by distance and pixel footprint; `0` disables it. Outline sample positions stay fixed. Fractional pixel widths avoid integer-radius popping. `--hatch-direction 0` follows surface U, `1` V, `2` +45°, and `3` -45° in the surface chart. Darker regions add strokes at fixed locations. Bloom threshold is in exposed linear HDR units and spacing is in output pixels for still captures. Bloom strength reduces both dot coverage and luminosity. `--bloom 0` disables bloom. `--ssaa 2` renders at twice each output dimension and downsamples stills; this costs four times the shading pixels.

Hatching follows authored surface UVs; optional shadow dots remain world-triplanar. Mip filtering blends unresolved strokes toward average coverage. The new hatching textures are generated reproducibly by `python -m inkforge.hatching`; their four channels are independent directional masks, including alpha. A contact sheet is in `output/hatching-texture-sheet.png`. Nested density maps preserve existing strokes as more are added. This is UV-based form following, not an automatic principal-curvature field solver. UV seams, distortions or poor charts can still interrupt strokes. Meshes without usable UVs get a planar fallback; curved meshes need suitable UVs. The generated USD spheres include latitude/longitude charts.

Dotted bloom is intentionally a fixed screen-space print lattice: its coverage changes as the light halo moves across it. Neither pattern uses time-varying noise. `--aa taa` is the default; `--aa none` disables temporal accumulation. `--shadow-fill .6` controls retained ambient light in shadow cores and `--penumbra-strength .55` controls edge stippling. The viewer exposes all three controls. TAA supports the renderer's static scenes and camera motion; it has no animated-object motion vectors or separate temporal AO history. Thin details and disocclusions can still shimmer or show short history artifacts. The pan clips and `tools.check_pan` provide motion evidence, not a claim of perfect temporal stability.

## Scene support

glTF/GLB: embedded/external assets, node transforms, core metallic/roughness materials, normal/AO/emission maps, vertex colors, two UV sets, KHR_texture_transform, KHR_materials_unlit, KHR_lights_punctual directional/point/spot lights, double-sided and alpha-mask geometry. Light transforms, colors, intensity, range and spot cones are imported. BLEND uses ordered coverage, not sorted transparency or refraction. Unsupported required extensions fail explicitly; export uncompressed core glTF for Draco/KTX assets. Animation, morphing and skeletal deformation are not evaluated.

USD/usda/usdc/usdz: OpenUSD stage composition, static visible Mesh prims, transforms, units/up axis, normals/UV primvars, material subsets, scalar PreviewSurface metal/roughness and basic UV textures. This is a PreviewSurface subset, not a complete USD renderer: no MaterialX, displacement, subdivision evaluation, animation, general shader networks, connected metal/roughness textures, or analytic shape prim tessellation. Polygon fan triangulation assumes convex faces; triangulate production inputs first. USD color textures currently use sRGB. The USD showroom is exported and loaded through OpenUSD for the gallery and round-trip test.

Local test assets: the supplied Bistro GLB, Khronos Sponza glTF, DamagedHelmet GLB, MetalRoughSpheres GLB, and the generated USD material showroom. The download helper records upstream sources/checksums and keeps upstream README/license information. Scene licenses are separate from renderer code.

USD lights: visible UsdLux distant, sphere/point and shaped spot lights are imported with transform, color, temperature and exposure. Dome lights use color/intensity only; dome textures are not sampled. Finite/area lights use a punctual approximation; IES, light linking, area-light integration and local-light shadow maps are not implemented. One primary directional source has cascaded shadows; additional directional and local lights are currently unshadowed.

## Performance and limitations

The AO correction measures **20.91 ms stationary, 30.50 ms moving (32.05 ms p95), and 30.23 ms with the day cycle**, on Bistro at **1974×1113**, with one renderer process and four 2048² cascades (`output/performance-bistro-1974x1113-surface-ao.json`). The previous revision measured 35.03/44.18 ms stationary/moving; these are separate offscreen runs, not a controlled simultaneous comparison. A pass-bypass profile at the saved café view identified full-resolution GTAO as about 20 ms of a 34 ms frame (`output/pass-cost-before.json`), motivating half-resolution evaluation rather than dropping the effect. Two concurrent viewer processes were also found and closed before validation. `output/ao-fix-review/comparison.png` and `output/surface-ao-pan.mp4` show the corrected look and camera motion. The 48-test suite includes actual GPU hatch sampling and camera-footprint invariance checks.

The latest Metal geometry/print-filter revision measures **35.03 ms stationary, 44.18 ms moving (49.88 ms p95), and 45.22 ms during the day cycle** on Bistro at **1974×1113**, retaining four 2048² cascades. These serialized offscreen measurements exclude presentation and are not directly comparable with the older 1280×800 table below. Results: `output/performance-bistro-1974x1113-printed-fast.json`. The new geometry path is checked against the retained five-pass path, and tiny print disks have an integrated-area regression. `output/printed-motion.mp4` records a 60-frame pan from the saved café view with the current quarter-amplitude motion jitter; thin-detail motion artifacts remain possible.

Measured on Apple M5 Pro / Metal, 1280×800, 4×2048 shadow maps, with lighter solid shadow cores, subtle stippled penumbras, density-modulated bloom, procedural sky and TAA:

| Scene | Triangles | Stationary mean | Moving mean | Moving p95 | Day cycle mean |
|---|---:|---:|---:|---:|---:|
| Bistro (stationary AA) | 2,828,266 | 44.07 ms | 64.19 ms | 72.95 ms | 68.35 ms |
| Sponza | 262,267 | 14.37 ms | 18.02 ms | 20.23 ms | 17.70 ms |

Raw results are `output/performance-bistro-1280x800-stationary-aa.json` and `output/performance-sponza-1280x800-fine-pen.json`; the Sponza measurement predates the AA fixes. Machine conditions varied substantially between sessions. A same-process old/new AA comparison (`output/taa-cost.json`) measured 44.65/45.28 ms stationary and 68.48/64.83 ms moving, so the higher total times here cannot be attributed to the stationary fix alone. These are wall-time measurements, not per-pass GPU profiles. Use F2 for the actual viewer rate. The RG32 caster maps add 64 MiB at 4×2048 compared with the former R32 maps; their normals require no extra raster pass. Validation covers 48 tests, including bent receiver acne, nearby tilted blockers, tiny stipples through magnification, clean sphere boundaries, filter continuity, bounded bloom energy and density, TAA silhouette error/camera-cut rejection, distant subpixel coverage and trails, resize resource reuse, smooth time progression, moving cloud shadows with generated and authored keys, importers and environments. `tools.check_aa` compares a diagonal silhouette with a 4×-per-axis reference downsampled in linear light. GPU regressions cover both ordinary and outlined silhouettes. The latest close Bistro capture and shadow-stage isolates are `output/closeup-review/current-*.png`; replay any viewer capture with `tools.capture_review`. These checks do not guarantee artifact-free shadows or temporal stability for every asset.

At frequency 32, planar hatch reprojection has 0.00284 mean absolute mask error over 322,722 samples on a 0–1 display-encoded scale (`output/pattern-stability.json`). This measures anchoring on a plane. Earlier showroom measurements in `output/ink-review/validation.json` predate the exact stationary resolve. `output/ink-review/cloud-shadows-{0,40}.png` shows the projected cloud field at two times. The native viewer was exercised with actual keyboard interaction; its automated native-window smoke also verifies two resize cycles and mouse capture/release. Import failure recovery and device reuse are covered through the drop-loading functions.

The distant-ink regression renders 0.225/0.45/0.9-pixel rails against both walls and sky, with stationary, slow-pan and fast-pan cases, a 4×-per-axis reference, a clear-background trail check and a camera cut. The full suite now has 48 passing tests, including stationary-cycle stability, live lighting, motion/style transitions and wall-time FPS calculations. At the current saved Bistro camera (1974×1113), with lighting/cloud time held fixed, the exact stationary resolve reduced distant-ink temporal deviation from 0.00384 to 0.000000027 (display-linear luminance). Whole-frame display-encoded deviation, including bloom, fell from 0.001335 to 0.00000919 (99.3%). These are 32-frame stationary measurements, not moving-camera scores. Reproduce with `tools.bistro_temporal_review capture.json --stationary`; results are in `output/stationary-review/bistro-temporal.json`. The prior distant-history comparison remains in `output/distant-ink/`.

`output/distant-ink-pan.mp4` records the previous moving-camera resolve over a 60-frame native 1280×722 pan, with moving clouds. `tools.pan --capture capture.json --label review --ssaa 1` reproduces this workflow; `--baseline` disables distant coverage history for A/B checks. The stationary resolve does not replace the motion-aware filter while the camera moves.

`tools.benchmark` warms eight frames per mode, measures forty stationary frames with cached cascades, forty moving-camera frames and forty frames with progressing time/clouds, and records CPU encoding/submission plus synchronized total wall time. It excludes loading, compilation, readback, PNG encoding and presentation. These are serialized frame timings, not GPU-only timestamps or measured display FPS; this Metal device/backend does not expose timestamp queries.

## Shareable app

`dist/Inkforge-Darwin-arm64.zip` contains a self-contained Apple silicon app, including Python, Slang, OpenUSD and shader resources. Recipients need no development environment. The relocated bundle passed USD and GLB renders and checks on 76 bundled native libraries. It is ad-hoc signed, not notarized. See [sharing and build instructions](docs/sharing.md) for Developer ID distribution, platform limitations and the comparison with the C++ `ntc_viewer` host.

Unused shadow texture arrays were removed from the lighting shader after the shadow-pass split: on the pinned Metal stack they caused the hatch samples to read incorrect data. A production rendering regression now checks sparse, directional crosshatches, and a shader probe checks that resolved stroke sites stay fixed as the camera footprint changes.

Material shader bindings are cached per pass/cascade. The pinned SlangPy/slang-rhi Metal backend incorrectly uses color-attachment count as render-target array length for multiple render targets. Metal now uses an alpha-tested depth prepass followed by a single early-depth-tested shading pass: position is a color attachment and the other four G-buffers use storage writes. This avoids repeating full material shading five times. Vulkan/D3D12 use MRT. The five-pass Metal path remains available for parity diagnostics. Exact facet normals are uploaded per triangle and fetched by primitive ID, avoiding derivative-sensitive shadow-plane reconstruction. Rasterizing all scene geometry for each cascade remains a significant cost. There is no occlusion culling, scene streaming, or meshlet renderer.

Lighting uses analytic sky/ground fill and an approximate environment specular term, not baked or ray-traced GI, environment convolution or traced reflections. Imported local lights use inverse-square attenuation and spot cones. Stylized lobe expansion deliberately changes energy. The PBR preset is a material/shading comparison, not a physically complete reference renderer.

## Research and attribution

- [Hi-Fi Rush: 3D Toon Rendering, GDC 2024](https://www.youtube.com/watch?v=gdBACyIOCtc): art direction across deferred lighting, shadows, AO and patterns. The video description and related material were accessible; the slide PDF was blocked, so this is not a claim of having reproduced the entire talk's implementation.
- The indexed text of the [official GDC slides](https://media.gdcvault.com/gdc2024/Slides/GDC%2Bslide%2Bpresentations/Tanaka_Kosuke_3D_Toon_Rendering.pdf) confirms 4×4 PCF shadow antialiasing. [Tango's CGWORLD interview](https://cgworld.jp/article/202306-hifirush02.html) describes adjusting hatching to be finer/lighter in cluttered scenes and applying patterns per lighting component. Those principles guided the continuous shadow filter and restrained bloom refinement; our implementation is independent, with no copied shader code.
- [Alexandre Lamure, Stylized GGX Shading](https://alexandrelamure.github.io/graphics-posts/stylized-ggx-shading.html): roughness-dependent lobe expansion. This renderer additionally bounds its expanded NDF denominator at the original peak to avoid singular highlights; it is an artistic variation of the formula.
- [Jimenez et al., Practical Realtime Strategies for Accurate Indirect Occlusion](https://www.activision.com/cdn/research/Practical_Real_Time_Strategies_for_Accurate_Indirect_Occlusion_NEW%20VERSION_COLOR.pdf), and [Intel XeGTAO](https://github.com/GameTechDev/XeGTAO): GTAO horizon integration. This implementation is not the complete XeGTAO pipeline and omits temporal filtering and hierarchical depth.
- [Polyphony GT7 reference](https://blog.selfshadow.com/publications/s2025-shading-course/pdi/supplemental/gt7_tone_mapping.cpp): the actual 2025 GT7 ICtCp/Rec.2020 mapping, not the older Gran Turismo/Uchimura curve. The unmodified MIT-licensed reference is in `third_party/gt7_tone_mapping.cpp`; its license notice is retained in the Slang port.
- [Praun et al., Real-Time Hatching](https://hhoppe.com/hatching.pdf): tonal art maps motivate nested stroke densities and surface parameterization. Current hatching uses a simple four-density tonal-map set on authored UVs; it does not implement the paper's curvature-field/lapped-texture system.
- [Gooch illustration research](https://www2.cs.utah.edu/gdc/projects/illustration/): warm/cool tone shading is another useful comic technique. Other useful directions are authored highlight masks, inverted-hull silhouettes, curvature-aligned strokes and material-specific palette ramps; these are not all implemented here.
- User examples [MscSzf](https://www.shadertoy.com/view/MscSzf), [4dVGRW](https://www.shadertoy.com/view/4dVGRW), [MsB3W1](https://www.shadertoy.com/view/MsB3W1): direct pages were blocked. [The original Noise Contour adaptation article](https://medium.com/hackernoon/converting-shaders-from-shadertoy-to-threejs-fe17480ed5c6) identifies MscSzf and describes its multipass contour/shadow processing. [PixelsWorld's documented 4dVGRW adaptation](https://milai.tech/products/PixelsWorld/docs/contents/GLSL/shadertoy.html) exposes its normal/depth edge detector. Our outlines are independently implemented plane-distance/normal discontinuity detection, avoiding edge extraction from busy albedo textures. MsB3W1's exact source was not verified; none of these shaders was copied.
- [SlangPy](https://slangpy.shader-slang.org/en/latest/), [glTF specification](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html), [USD Preview Surface](https://openusd.org/release/spec_usdpreviewsurface.html), and [Filament PBR](https://google.github.io/filament/main/filament.html).
- [KHR_lights_punctual](https://github.com/KhronosGroup/glTF/blob/main/extensions/2.0/Khronos/KHR_lights_punctual/README.md) and [UsdLux](https://openusd.org/dev/user_guides/schemas/usdLux/overview.html) document light transforms, intensity, cone shaping and normalization. The USD finite-light conversion here is an approximation.
